## Autonomy & Spec Kit pipeline

### Autonomy & Spec Kit pipeline (NON-NEGOTIABLE)
- **Day-to-day implementation is autonomous**: file reads/writes, tests, type checks, and refactors MUST proceed without interrupting for minor naming or style preferences.
- **Spec Kit chained run**: new features MUST use `specify → clarify → plan → tasks → analyze → implement`, then stop. After **clarify**, pause for the user only if `[NEEDS CLARIFICATION]` remains, the spec quality checklist still fails, or Outstanding / high-impact Deferred items remain. Answered questions already written into the spec do not require a second confirmation — continue immediately to plan. After **analyze**, pause for the user if any CRITICAL / HIGH / MEDIUM finding exists; zero findings or only LOW → continue immediately to implement. After **implement**, do not start `/speckit-converge`. Review the diff first (`review-code`). Match `agent-roles` checkers and reviewers to changed files by each file's Scope (a mixed diff runs every match). After a role matches, read the versions its Scope names and judge against those, not a default major. Run `/speckit-converge` only after Blocking fixes, so ADR and the living spec match the final code. Do not add extra “does this plan look OK?” gates. `/speckit-checklist` is optional and not part of the default chain. Details: [`.agents/AGENTS.md`](../../.agents/AGENTS.md), [`.cursor/rules/speckit-pipeline.mdc`](../../.cursor/rules/speckit-pipeline.mdc).
- **Critical review still required**: breaking changes, architecture-boundary moves, and schema changes MUST be reviewed with the user. Everyday implementation details use recommended practice without a stop.
- **Destructive commands**: `git reset --hard`, `git push --force`, and bulk unconfirmed file deletion MUST NOT run without explicit user instruction.
